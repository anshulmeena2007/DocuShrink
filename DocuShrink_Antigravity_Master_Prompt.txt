DOCUSHRINK — COMPLETE PRODUCTION-READY WEB APPLICATION

You are an expert senior full-stack web engineer, frontend engineer, JavaScript engineer, UI/UX designer, accessibility specialist, SEO specialist, performance engineer, security engineer, and QA engineer.

Your task is to BUILD, RUN, TEST, FIX, VERIFY, AND DOCUMENT a complete production-ready website called:

DocuShrink

Tagline:
Simple tools for your files. Private by design.

The website should be an original online file/document/image utility platform inspired by the general concept of multi-tool websites such as iLovePDF, but it must NOT copy their branding, logo, colors, text, layout, illustrations, source code, or proprietary design.

Create a completely original DocuShrink identity and user experience.

==================================================
1. PRODUCT VISION
==================================================

DocuShrink is a collection of easy-to-use online utilities for images and documents.

Core philosophy:
Fast tools. Simple interface. Privacy-first processing.

Whenever technically possible, files should be processed entirely inside the user's browser.

There must be:
- No unnecessary backend
- No image upload server
- No account requirement
- No registration requirement
- No unnecessary database
- No server-side storage of user files

The initial version should prioritize tools that can reliably run client-side.

==================================================
2. ARCHITECTURE
==================================================

Build the application as a static/client-side web application wherever possible.

Use browser APIs for local processing:
- File API
- Blob API
- Canvas API
- URL.createObjectURL()
- FileReader
- Web Workers where useful
- JSZip for ZIP creation
- PDF.js where appropriate for client-side PDF rendering
- pdf-lib where appropriate for PDF manipulation

Do not create a backend simply because a feature is difficult.

If a feature cannot reliably be implemented client-side, clearly mark it as:
Coming Soon

Never pretend a non-functional feature works.

13. TARGET SIZE PRESETS
==================================================

Add:
- Compress to ~50 KB
- Compress to ~100 KB
- Compress to ~200 KB

Implement intelligent target-size compression.

Approach:
1. Generate image.
2. Measure Blob size.
3. Adjust quality.
4. Use binary-search-like optimization.
5. If quality reduction is insufficient, reduce dimensions.
6. Generate again.
7. Continue until a reasonable result is reached.

Do not guarantee exact file size.

Display:
Target size: ~100 KB
Result: 94 KB

If target cannot reasonably be reached:
Best achievable result: 126 KB

Never fake file sizes.
